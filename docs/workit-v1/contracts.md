# Workit v1 shared data and operation contracts

Status: Final specification reference, written 2026-09-03. Records the contract
decisions approved during review of [the product specification](spec.md).
This is documentation, not an implemented API or authorization to execute work.

## 1. Format and ownership

Use JSON objects with camelCase keys. The TypeScript notation below specifies
serialized fields, not a dependency on a TypeScript-aware host. Every field is
required unless marked optional; nullable fields use explicit `null`. Reject
unknown fields, invalid enum members, malformed values, and unsupported schema
versions at the shared boundary. Do not silently coerce strings to booleans,
discard fields, or apply permissive defaults.

- `schemaVersion: 1` identifies this format. An incompatible format receives a
  new integer version; readers do not rewrite unsupported records.
- `policyVersion: "1.0.0"` identifies the initial resolver rule implementation.
  Change this version when rule behavior changes, independently of storage and
  package versions. Encode it as three nonnegative decimal components without
  leading zeros, separated by dots. Record the resolved constraints with the
  policy inputs. An unknown policy version may be displayed as historical data,
  but cannot authorize work until explicit reassessment with supported rules.
- A `Revision` is an opaque UUID, replaced on every committed snapshot update.
  Compare for equality, not order. Recovery also issues a new revision so an
  old client's revision cannot accidentally match a restored snapshot.
- `Id` is a lowercase UUID generated by core. `Digest` is a lowercase, 64-digit
  SHA-256 hex string. `Utc` is an ISO timestamp ending in `Z`; timestamps are
  descriptive, not proof of ownership, ordering, or approval freshness.
- Paths are checkout-relative, use `/`, and cannot escape the checkout through
  `..`, an absolute path, or a symlink. Scope paths name files or directories;
  `.` explicitly names the checkout. Empty paths mean no file scope, not all
  files. There is no glob or executable-expression language in this contract.
- Hash file contents as their exact bytes. For structured snapshots, hash UTF-8
  JSON with recursively sorted object keys and no insignificant whitespace;
  preserve array order and string contents. Numbers must be finite safe
  integers. Reject invalid Unicode strings; do not normalize approved text.

The shared core validates all payloads. Native tool schemas and CLI parsing must
match that contract rather than maintain independent policy implementations.
Stored record types are not accepted as mutation payloads. In particular,
provenance, revisions, policy conclusions, and lifecycle state are core-owned.

```typescript
type Id = string;
type Revision = string;
type Digest = string;
type Utc = string;
type Host = "opencode" | "cursor" | "codex_cli" | "codex_desktop" | "pi" | "workit_cli";
type Assurance = "enforced" | "agent_guided" | "unavailable";
type Outcome = "verified" | "accepted_limitations" | "stopped";
type Scope = { description: string; paths: string[]; exclusions: string[] };
type Ref =
  | { kind: "file"; path: string; digest: Digest | null }
  | { kind: "record"; collection: "evidence" | "decisions" | "findings" | "workers"; id: Id }
  | { kind: "host"; host: Host; handle: string }
  | { kind: "external"; url: string };
type Provenance = {
  kind: "host_observed" | "agent_reported" | "imported";
  host: Host;
  session: Ref | null;
  workerId: Id | null;
  receipts: Ref[];
};
type Entry<T> = { id: Id; recordedAt: Utc; provenance: Provenance; data: T };
type Fact = { statement: string; basis: "observed" | "inferred" | "unknown"; refs: Ref[] };
type Signal = {
  value: boolean | "unknown";
  basis: "observed" | "inferred" | "unknown";
  reason: string;
  refs: Ref[];
};
type Constraint = {
  id: string;
  kind: "host" | "project" | "user";
  statement: string;
  source: Ref;
  acceptanceAllowed: boolean;
  requires: {
    kind: "check" | "method" | "decision";
    scope: Scope;
    refs: Ref[];
    method: Dimension | null;
    before: "dependent_action" | "write" | "close";
    dependentAction: string | null;
  }[];
};
type Intent = { objective: string; scope: Scope; authorityRefs: Ref[] };
type Progress = {
  summary: string;
  nextAction: string | null;
  blockers: { reason: string; dependentAction: string; refs: Ref[] }[];
};
```

References are locators, not authority. Validate record references against their
task or identified import origin. A missing file digest cannot establish file
freshness. Do not persist credentials, authentication headers, signed secret
URLs, or raw conversation logs in references or summaries.

Adapters supply provenance from the actual invocation and available native
evidence, outside the agent-editable payload. A supplied receipt locator is not
itself a validated receipt. Caller identity, command-line confirmation flags,
and claimed consent must not be upgraded to observed human approval. Native
observations can attest that a tool ran without attesting that its output proves
correctness. Imported provenance never grants destination authority.

## 2. Assessment, policy, and evaluation

```typescript
type Assessment = {
  facts: Fact[];
  signals: {
    approachUnknown: Signal;
    productChoiceOpen: Signal;
    behaviorChange: Signal;
    mechanicalLowRisk: Signal;
    durableAgreementNeeded: Signal;
    coordinationPlanNeeded: Signal;
    helperUseful: Signal;
    testFirstPractical: Signal;
  };
  consequences: {
    area:
      | "behavior"
      | "public_contract"
      | "data"
      | "security"
      | "operations"
      | "reversibility"
      | "consumers";
    fact: Fact;
  }[];
  verification: { claim: string; scope: Scope; availableChecks: Ref[]; gaps: string[] }[];
};
type Dimension =
  | "investigation"
  | "challenge"
  | "artifacts"
  | "testing"
  | "verification"
  | "review"
  | "delegation"
  | "continuity"
  | "decisions";
type Requirement = {
  id: Digest;
  ruleId: string;
  dimension: Dimension;
  scope: Scope;
  reason: string;
  satisfaction: string;
  before: "dependent_action" | "write" | "close";
  dependentAction: string | null;
  acceptanceAllowed: boolean;
};
type Policy = { policyVersion: string; inputDigest: Digest; requirements: Requirement[] };
type PolicyChange = {
  recordedAt: Utc;
  fromInputDigest: Digest | null;
  toInputDigest: Digest;
  added: Digest[];
  retired: Digest[];
  reason: string;
};
type RequirementEvaluation = {
  requirementId: Digest;
  status: "satisfied" | "unsatisfied" | "accepted_limitation" | "unavailable";
  evidenceIds: Id[];
  decisionIds: Id[];
  reason: string;
};
type Capability = {
  name: string;
  surface: string;
  assurance: Assurance;
  reason: string;
  refs: Ref[];
};
```

All eight signal fields are required. `value: "unknown"` pairs only with
`basis: "unknown"`; known booleans pair with observed or inferred basis.
Observations require supporting references; inferences require their reasoning.
An explicit unknown is valid input, not a missing-field error. Unknown signals
restrict only dependent actions and never silently resolve to false. A
contradiction such as behavioral change and a wholly mechanical change both
being asserted true requires reconciliation, not a permissive tie-break.

Constraints come from the actual host, project, and user context. Their
`requires` entries normalize applicable check, method, and decision obligations;
free-form statements are explanations, not keyword-based executable rules.
A method obligation names its dimension; check/decision obligations have a null
method and references identifying the required check or decision. Unresolved
constraint meaning must be surfaced as uncertainty before dependent work.
Assessment submission cannot replace constraints or change which allow acceptance.
`satisfaction` explains a requirement; it is not executable code. `ruleId`
identifies a rule in the versioned core catalog, whose logic determines whether
the evidence or decision satisfies the requirement. There is no user-authored
predicate language.

Normalize unordered sets, scopes, references, and constraints before resolving.
The input digest covers the assessment, intent, resolved constraints, relevant
prior obligations/decisions/findings, and policy version. Storage revisions,
new record IDs, timestamps, and host presentation are not random resolver inputs.
Requirement IDs derive deterministically from rule ID, normalized scope, and
satisfaction boundary; unchanged obligations retain their identities. The
resolver has no file, tool, network, or model side effects.

Requirement evaluations and capability mappings are separate from requirements.
Agent submissions cannot set evaluations. A valid assessment can be recorded
successfully while its resulting policy still requires input or blocks work.
Do not misreport that successful recording as permission to proceed.

## 3. Evidence, decisions, findings, and workers

```typescript
type Candidate = {
  id: Digest;
  scope: Scope;
  completeness: "known" | "uncertain";
  files: {
    path: string;
    kind: "file" | "symlink" | "absent";
    digest: Digest | null;
    executable: boolean | null;
  }[];
  environment: { name: string; value: string | null; refs: Ref[] }[];
  head: string | null;
};
type Evidence = {
  kind: "check" | "review" | "investigation" | "artifact";
  claim: string;
  requirementIds: Digest[];
  beforeCandidateId: Digest | null;
  candidateId: Digest | null;
  result: "passed" | "failed" | "missing" | "skipped";
  summary: string;
  refs: Ref[];
  exitCode: number | null;
  reviewContext: Ref | null;
};
type EvidenceEvaluation = {
  evidenceId: Id;
  status: "passed" | "failed" | "missing" | "skipped" | "stale";
  reason: string;
};
type Decision = {
  purpose: "design" | "action" | "limitation" | "preference";
  binding: {
    taskId: Id;
    workspaceId: Id;
    scope: Scope;
    presented: string;
    approvedContent: string;
    contentRefs: Ref[];
  };
  digest: Digest;
  response: "approved" | "rejected";
  requirementIds: Digest[];
  revoked: { at: Utc; reason: string } | null;
  consumption: { state: "reserved" | "consumed" | "uncertain"; at: Utc; actionRef: Ref } | null;
};
type Finding = {
  claim: string;
  consequence: string;
  scope: Scope;
  candidateId: Digest | null;
  refs: Ref[];
  disposition: "open" | "fixed" | "dismissed" | "deferred";
  resolution: { reason: string; evidenceIds: Id[]; decisionIds: Id[] } | null;
};
type Assignment = {
  role: "investigator" | "reviewer" | "implementer";
  objective: string;
  scope: Scope;
  decisionIds: Id[];
  requirementIds: Digest[];
  candidateId: Digest | null;
  stoppingCondition: string;
};
type WorkerReport = {
  outcome: "completed" | "failed" | "cancelled";
  summary: string;
  evidenceIds: Id[];
  findingIds: Id[];
};
type Worker = {
  assignment: Assignment;
  state: "assigned" | "running" | "cancelling" | "stopped" | "unknown";
  session: Ref | null;
  report: WorkerReport | null;
};
type Owner = { taskId: Id; workerId: Id | null; session: Extract<Ref, { kind: "host" }> };
```

Candidate identity hashes its normalized scope, complete file inventory for that
scope, resolved environment names/values, and completeness. Sort environment
entries by name and reject duplicate names. Receipt/reference IDs are provenance,
not environment identity: new receipts for unchanged values must not make the
candidate different. Capture only relevant non-secret values; null values remain
unidentified limitations, not guessed matches. Git HEAD is context,
not sufficient identity: include relevant uncommitted/untracked files, additions,
deletions, executable bits, and symlink targets. An absent path has a null digest;
a file hashes its bytes and a symlink hashes its target text. Only absent entries
have a null digest; file executable bits are booleans, while symlink/absent
executable fields are null. Do not follow an
out-of-scope link. An uncertain dependency scope requires conservative freshness
evaluation. Missing environment identity is a limitation, not a guessed match.

Original evidence results remain observations. Freshness is a derived evaluation;
callers cannot submit `stale: false`. A check or review needs an applicable
candidate to satisfy a code-state requirement. `beforeCandidateId` and
`candidateId` identify the captured start and end state for a check or review;
changes during a check cannot be hidden by attaching only the end state. Missing
captures remain a limitation. Historical evidence such as a genuine pre-fix RED
check can support its historical claim without being called a passing check on
the final candidate. A fresh-context review additionally needs an actual separate
review context, not an author-supplied assertion of independence. A skipped or
missing result requires a reason; exit zero and an artifact's existence do not establish
the requested behavior on their own.

Core computes each decision digest over its purpose, binding, and requirement
IDs, preserving the exact presented/approved content. Whole-document approvals
include a file content reference with the exact approved byte digest. Approvals
of a particular decision bind that decision snapshot, not unrelated document
sections. `record` cannot set revocation, consumption, or provenance. Relevant
content or scope drift invalidates applicability without erasing the old record.
An action decision
authorizes only its stated bounded action/workflow, not standing permission;
core reserves its bounded execution under the metadata lock before invoking an
external effect. Competing invocations cannot consume the same one-time grant.
Success marks it consumed; an ambiguous outcome keeps it uncertain and blocks
blind retry. Only core can release a reservation after establishing that the
effect did not occur and that retry remains authorized. A bounded workflow's
reservation covers only its approved remaining steps, not repetition of completed
steps or unrelated actions. Agents cannot set or clear consumption. Design
decisions remain applicable to unchanged approved intent. Rejecting a decision
never satisfies a requirement. A limitation can affect closure only when the
applicable requirement permits acceptance.

Finding resolution requires a reason and the relevant evidence or decision.
`fixed` requires supporting verification; unsupported findings can be dismissed
with evidence-backed reasoning. Deferring an in-scope blocking finding needs an
applicable permitted acceptance, not just `disposition: "deferred"`. Resolved
findings remain visible, and new evidence can reopen them.

Only implementers may receive helper writer ownership. The lead is represented
by `workerId: null` and an observed session reference. Assignment is not launch,
ownership, or permission to delegate further. Native adapters bind actual worker
sessions and lifecycle observations. A worker report is a claim about its result,
not proof that its process has stopped or that its findings are resolved.
Cancellation requests retain ownership until the worker is safely stopped or
explicitly accounted for. Unknown worker state requires recovery.

## 4. Stored snapshots and read views

```typescript
type Closure = { outcome: Outcome; at: Utc; summary: string; decisionIds: Id[]; evidenceIds: Id[] };
type TaskRecord = {
  schemaVersion: 1;
  id: Id;
  workspaceId: Id;
  revision: Revision;
  createdAt: Utc;
  updatedAt: Utc;
  origin: { workspaceId: Id; taskId: Id; exportDigest: Digest } | null;
  intent: Entry<Intent>;
  constraints: Constraint[];
  status: "active" | "paused" | "closed";
  closure: Closure | null;
  progress: Progress;
  assessments: Entry<Assessment>[];
  policy: Policy | null;
  policyChanges: PolicyChange[];
  candidates: Candidate[];
  evidence: Entry<Evidence>[];
  decisions: Entry<Decision>[];
  findings: Entry<Finding>[];
  workers: Entry<Worker>[];
};
type WorkspaceRecord = {
  schemaVersion: 1;
  id: Id;
  revision: Revision;
  root: string;
  writer: { state: "held" | "uncertain"; owner: Owner; acquiredAt: Utc } | null;
};
type TaskView = {
  task: TaskRecord;
  workspace: WorkspaceRecord;
  capabilities: Capability[];
  requirements: RequirementEvaluation[];
  evidence: EvidenceEvaluation[];
};
type TaskSummary = {
  id: Id;
  revision: Revision;
  workspaceRevision: Revision;
  objective: string;
  status: "active" | "paused" | "closed";
  closure: Closure | null;
  progress: Progress;
  policy: Policy | null;
  requirements: RequirementEvaluation[];
  writer: WorkspaceRecord["writer"];
};
type ExportBundle = {
  schemaVersion: 1;
  exportedAt: Utc;
  sourceWorkspaceId: Id;
  task: TaskRecord;
  digest: Digest;
};
```

Use `.workit/tasks/<id>.json` and `.workit/workspace.json` as specified in the
product document. The canonical absolute root belongs only to this local
workspace identity, not portable task paths. The workspace writer is the only
authoritative ownership record. Task summaries are projections, not extra files.
Compact context uses summaries and selected references; do not inject full
history into every prompt.

New tasks start active, with no closure and no policy conclusion until assessed.
An unresolved assessment/policy does not authorize dependent product writes;
safe authorized investigation may continue. Only closed tasks have a closure.
Closed tasks are not silently reopened; further
work starts a new task referring to the previous context. Ordinary scope,
progress, assessment, evidence, finding, and worker mutations require an unclosed
task. Explicit decision revocation or state recovery can update a closed record
without reopening it or rewriting its historical closure. Paused tasks allow
scoped metadata/recovery work, but not product-write ownership or new worker
execution until resumed. Progress updates cannot
remove findings, modify requirements, or grant authority.

After interruption, policy changes, or import, reevaluate applicability against
current observations. Inspection can report derived staleness or needed recovery
without writing it back. It never initializes, repairs, migrates, or launches a
model session. Historical verified closure describes the candidate verified at
closure, not arbitrary subsequent edits.

Export excludes live ownership and credentials. Hash the bundle excluding its
own `digest` field. Import validates the bundle and creates a new paused task
with new destination identity/revision, no closure, no live worker sessions, and
imported provenance. Preserve source bindings as historical context; they do not
authorize destination actions. Imported worker entries describe source history,
not destination workers: they cannot own, resume, or require cancellation of a
destination process. Resolve current constraints and capabilities from the
destination rather than activating imported host constraints. Resume requires
reconciliation and an applicable current request/authority. This defines
v1-to-v1 transfer; legacy continuation follows section 17 of the product spec.

## 5. Purpose-specific public operations

Expose eight named tool families: `workit_task`, `workit_policy`,
`workit_evidence`, `workit_finding`, `workit_decision`, `workit_worker`,
`workit_writer`, and `workit_state`. Each has a closed `action` enum and a
validated per-action payload. CLI names are `workit <family> <action>`, replacing
underscores in action names with hyphens. Native UI may present different labels;
shared operation names and meanings remain the same. These are direct core
operations, not a network service or general command-dispatch language.

Every request includes `schemaVersion: 1` and `action`. Existing-task operations
include `taskId`. Mutations include `expectedRevision`; workspace-sensitive
operations also include `expectedWorkspaceRevision`. New task/import requests
have no task revision, but bind the expected workspace revision. Explicit initial
task creation can initialize an absent workspace using an expected workspace
revision of `null`; explicit import has the same initialization allowance. Read
operations cannot initialize state. Caller context identifies the actual
workspace, actor, native evidence, and constraints outside the model payload.

The following table supplies the remaining payload fields and success data.
There are no unspecified generic object payloads or arbitrary state patches.

The workspace-sensitive set is task start/revise/pause/resume/close, worker
assign/report/cancel, writer acquire/release, and state import/recover. A valid
task revision is also checked where an existing task participates. Ownership is
rechecked for every controlled product-write action, not only explicit writer
calls. All helpers, including implementers, are prohibited from recording or
revoking user decisions, changing task scope/lifecycle, accepting exceptions,
assigning further helpers, or closing the lead's task. Helpers can inspect their
assigned context, report evidence/findings, and submit their own worker report;
implementers can additionally acquire/release their own authorized writer scope.
They cannot resolve away blocking findings on behalf of the lead. Requests for
another worker's identity/scope or a broader task-control operation are denied.

These bounded metadata reports use the serialized core lock and revision checks;
they do not require or grant repository writer ownership. Native read-only
workers may use them but cannot edit `.workit/` files directly. Writer release
is limited to the current validated owner; the lead must use cancellation and
recovery rules rather than release another actor's ownership by assertion.

Native observations populate candidates, constraints, provenance, session binding,
worker lifecycle, and decision consumption through validated adapter entry points.
They are not extra agent-callable setters. Where an observation is only
agent-reported, retain that limitation. Adapters cannot use these entry points to
bypass core validation or claim stronger assurance than the actual host supports.

Pause and close must not leave an uncontrolled worker running. If cancellation
is pending or termination cannot be established, report that state and the
blocking condition instead of claiming the requested transition completed.
`task.close` requests an outcome; it does not dictate it. Core checks current
requirements, evidence, decisions, findings, and ownership. Unsatisfied requested
verified closure fails; do not silently substitute accepted-limitations closure.

These names cover the shared task/policy protocol. Installation/diagnostics and
optional delivery integrations remain separate commands/tools with the product
scope specified in sections 12 and 13; they cannot mutate these records directly.

## 6. Responses, conflicts, and recovery

```typescript
type ErrorCode =
  | "invalid_input"
  | "unsupported_version"
  | "not_found"
  | "invalid_transition"
  | "revision_conflict"
  | "needs_input"
  | "permission_denied"
  | "capability_unavailable"
  | "requirements_unsatisfied"
  | "writer_conflict"
  | "recovery_required"
  | "storage_error"
  | "external_outcome_unknown";
type ErrorDetails = {
  fields?: { path: string; reason: string }[];
  taskId?: Id;
  expectedRevision?: Revision;
  actualRevision?: Revision;
  expectedWorkspaceRevision?: Revision | null;
  actualWorkspaceRevision?: Revision | null;
  requirementIds?: Digest[];
  capability?: string;
  owner?: Owner;
  path?: string;
  operation?: string;
  outcome?: "not_started" | "pending" | "unknown";
};
type Result<T> =
  | {
      ok: true;
      schemaVersion: 1;
      revision: Revision | null;
      workspaceRevision: Revision | null;
      data: T;
    }
  | { ok: false; schemaVersion: 1; code: ErrorCode; error: string; details: ErrorDetails };
```

Use stable codes for programmatic behavior and readable `error` text for people.
`invalid_input` identifies offending fields; `revision_conflict` includes expected
and actual revisions; `requirements_unsatisfied` identifies the unsatisfied
requirements; `capability_unavailable` names the missing capability;
`writer_conflict` identifies the owner. Corrupt records or uncertain ownership
use `recovery_required`, not an empty/default task. Unsupported versions are
reported explicitly and left untouched. CLI JSON preserves this shape; human
output may summarize it. CLI success exits zero; failed operations exit nonzero.

Under the short metadata lock, validate task and workspace preconditions before
mutating the authoritative record. Each file replacement is atomic; this is not
a promise of a transaction across files or a native worker launch. For a worker
handoff, reserve ownership before permitting writes. If a later file update or
native action fails, retain that reservation/uncertainty and reconcile it; never
grant another writer on the strength of a partially updated task projection.
After an ambiguous response, inspect actual state before retrying. No automatic
merge, blind retry, duplicate native launch, or generic retry daemon is required.

Recovery of corrupt bytes uses `expectedBytes` as the compare-and-swap condition
when the current revision cannot be decoded; it is the sole exception to normal
revision input. `snapshotDigest` selects the validated current snapshot or a
validated recovery copy. Preserve the damaged bytes, verify the selected copy
and actual worker state, then write a
fresh revision. Restored live work remains paused until reconciled; a historical
closed record remains historical. Never restore a previous writer as active or
reuse an old approval as newly granted authority. An uncertain owner is not
cleared until its process is stopped or explicitly accounted for. Recovery is
local and explicit; import, setup, and read calls cannot invoke it implicitly.

Behavioral checks must cover malformed/unknown inputs, unsupported versions,
stale updates including post-recovery stale clients, forged provenance attempts,
evidence becoming stale, refused false closure, conflicting writers, cancellation
uncertainty, one-time approval reservation and ambiguous effects, helper authority,
stable environment fingerprints, partial updates, and side-effect-free reads. Test these shared
contracts once at core boundaries, then test each adapter's mapping and actual
assurance instead of duplicating every assertion per host.
