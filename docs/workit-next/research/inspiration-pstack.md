## 1. Inventory

pstack = a Cursor plugin of plain Agent-Skills folders (`.cursor-plugin/plugin.json`; installed via `/add-plugin pstack`). Almost every SKILL.md has `disable-model-invocation: true`, so skills fire only by slash command or by being named in another skill's text (explicit routing, not auto-trigger). Only `unslop` ("Must always apply") and `typescript-best-practices` are ambient.

**Router (one entry point):** `skills/poteto-mode/SKILL.md` — sticky "mode" (`mode: true`, `reminder:` frontmatter). Matches the task to a playbook, copies the playbook's steps verbatim into the todo list (skipped steps stay with `skip: <reason>`), routes to other skills as steps fire. Subagent wrapper: `agents/poteto-agent.md` (reads poteto-mode SKILL.md in full first, so children inherit the same operating manual). Second agent: `agents/comment-sicko.md`.

## 2. End-to-end flow of a unit

1. **Intake:** `/poteto-mode <request>`. Router decides playbook (poteto-mode SKILL.md "Playbooks"). Before asking the human a "which approach" question it classifies: if the answer is observable by running something -> Prototype playbook decides, human asked only for true product/preference calls (SKILL.md Non-negotiables bullet 2). Principle: never-block-on-the-human.
2. **Plan/design:** `how` over affected subsystem; `architect` (parallel design exploration via arena) when code crosses a function boundary; name the data shape first (`principle-model-the-domain`); write a 4-item "throughput checkpoint" todo: blocking first steps, independent workstreams, shared mutable state, smallest safe decomposition (`playbooks/feature.md` step 3). Big work: `multi-phase-plan` playbook emits a checklist file (below).
3. **Implement:** delegation is mandatory in `feature.md` step 4: lead owns design/review/verify; a subagent (default model per role) writes code with named files, data shape, success criteria; "commit liberally"; arena instead if multiple valid shapes. Lead reviews the diff and writes its own summary ("You own every subagent's work").
4. **Verify (self):** on the matching surface via `control-ui`/`control-cli`; "Inconclusive or wrong-surface is not a pass" (feature.md step 5). Bug fix: repro it yourself first, never ask the user to repro unless the control surface truly cannot reach it (bug-fix.md step 1); failing repro committed before the fix (step 5), paste failing-then-passing output verbatim in the reply. Verdict vocabulary `VERIFIED / NOT VERIFIED / INCONCLUSIVE` (figure-it-out Phase C). Prove-it-works: "Script the check when you can... a deterministic script that re-runs the same comparison".
5. **Clean:** `/deslop` before commit, `/no-comments` before review, `technical-writing` + `unslop` on PR text (opening-a-pr.md "PRs").
6. **PR:** small ordered commits rebased from liberal ones ("Each commit is a future PR"); Conventional Commit title; body sections `## Why / What changed / Scope / Tradeoffs / Blast Radius / Verification`, squash body <~40 lines; opened ready, never draft (opening-a-pr.md).
7. **Review:** `interrogate` (multi-model adversarial) when design contested; bot comments (Bugbot) triaged skeptically fix/dismiss/ask per `references/bugbot-triage.md`, third pass leans dismiss except security/auth/billing/data/migrations.
8. **Merge:** Babysit (`babysit.md`) drives to merge-ready, order conflicts -> review threads -> CI, batch fixes into one push; stops at human line. Shipping (`shipping.md`) is a separate, explicitly requested step: independent per-PR verdict from an agent that did not write the code, land contiguous verified run from the stack root, one PR at a time, recompute after each merge.
9. **Not a meat proxy:** the human is moved out of the verification loop by (a) mandatory runtime repro/verification on the real surface through a project-local control/verify skill (`create-verification-skill` generates `.cursor/skills/verify-<app>/` with Launch/Doctor/Drive/Evidence/Cleanup + feature map, proven end-to-end once before hand-off); (b) author != verifier (fresh agent, different model family) and CI/bot approval explicitly "not a verdict" (shipping.md step 1); (c) evidence-in-reply rule: every claim labeled measured/inferred/guess, "never hand the human a check you could run" (SKILL.md "Writing the reply"); (d) human review reserved for interaction-changing PRs, delivered as screenshots + 30-60s video in chat (multi-phase-plan "Review gate"). Autopilot-full: "The operator's full-autonomy grant plus the root's clean verdict is the merge authorization" (autopilot-full.md step 5).

## 3. Deterministic vs LLM split

**Deterministic (scripts/CLI):**
- `orch` (Bun + commander; `scripts/orch/orch.ts` 578 loc, `store.ts` 1607 loc, tests). Plain-file store at `orchestrate/<slug>/` in the agent store, "exactly one writer per file", `.orch.lock` with dead-pid stealing, atomic writes (`atomicWrite`). Commands: `init`, `unit add|set|list` (`--brief --branch --pr --sha --state --track`), `ledger record|check` (`--verifier`), `inbox push|drain` (`--report`, `--peek`), `gate` (open/resolve), `frontier set --repo`, `standing` (preferences.md), `status` (regenerates `status.md`); global `--json --force`. Formats: `units.tsv` header `id track state branch pr sha brief`; `ledger.tsv` `pr sha verdict evidence verifier ts` with verdict enum `live-ui-verified | unit-test-verified | type-check-only | verifier-blocked | verifier-failed`; `inbox/<ts>-<pid>-<uuid>.tsv` completion pointers; `gates.md` (question, options, default-on-no-answer); `frontier.json` `{ordered PRs, branches, head SHAs, generation, lowest unmerged}` (computed from Graphite `gt` — contradicts the "never require gt" rule elsewhere, see anti-patterns); `preferences.md` standing orders; `overview.md` append-only PR DB. Ledger rule: "A new head SHA voids the row" — verification is keyed by (PR, head SHA) (orchestrate.md "Verification"). CLI "never spawns, waits, or wakes anything" — agents spawn only via Task.
- `watch-pr` (TS): polls one PR / connected stack / frozen queued stack; JSON (NDJSON) default, `--pretty`, `--status-only`, `--stack`, `--queued-stack --stack-prs a,b,c`, `--interval 60`, `--sweep-interval 300`, `--timeout`, `--max-query-errors 5`, `--allow-draft`. Branded `PrNumber`, typed `CiState` union (`ci-clean|ci-pending|ci-failing|ci-github-rejected`), merge blockers (`merge-conflicts|review-threads|failing-checks|merge-gate`), verdicts `READY|WAITING(reason merge-queue)|ADVANCE|COMPLETE`; counts Bugbot passes; treats review text as untrusted data. Output drives agent wakeups ("never add a second sleep loop").
- `check-plan.mjs` (185 loc): lints a multi-phase plan file for required headings, per-PR sub-blocks (`Depends on / Files / Build / You see / Verify, unit / Verify, live / Verify, perf / Review gate / Merge`), the verbatim verification rule, "Ten lanes on `<model>` at the PR head", perf items `Metric/Probe/Baseline/Rule`, box syntax. Output = lines the agent must fix.
- `worktree-audit.sh`: read-only; classifies worktrees by size/age/merged/dirty/remote/PR/last chat -> bucket suggestion; never deletes.
- `show-me-your-work/scripts/log.sh`: append TSV row (`ts phase decision why evidence result`), strips tabs/newlines, quotes leading `=+-@` (spreadsheet formula injection).
- `git patch-id`, `git merge-tree`, `git merge-base --is-ancestor`, `--force-with-lease` after `ls-remote` are used as deterministic gates in prose (shipping.md step 3, autopilot-full step 5).
- Prose-level determinism via structure: todo list seeded verbatim from playbook; `principle-encode-lessons-in-structure`: "same instruction a second time -> lint/script/flag"; `principle-build-the-lever`: "if you cited it and there is no codemod/script/generator in the diff, you didn't apply it."

**LLM-judgment:** playbook selection, brief authoring, design, code, triage fix/dismiss/ask, verdicts of lane agents, flake-vs-real CI classification, drain classification (landed/needs-verify/failed/zombie/noise), reply writing. Everything is markdown instructions; there is no state machine runtime outside `orch`/`watch-pr`.

## 4. Parallelism

- Philosophy (README): "fearless parallelism... when you can go deep on one agent and trust it to write good, verifiable code, you can truly parallelize"; start N agents each with `/poteto-mode`.
- One writer per worktree/branch; every subagent inherits or gets its own worktree; `principle-separate-before-serializing-shared-state`: eliminate shared mutable target first ("`indexer-state.json` + `metrics-state.json` is not" shared mutation), lockfiles only for real invariants. Guide pitfall: "Parallel agents in one worktree... overwrite each other".
- Default Task config: `run_in_background: true`, file pointers not inlined context, explicit model per role (SKILL.md "Subagents"); fresh subagent per new work with consolidated scope (original brief + all later directives + prior report + branch), resume only when state lives in the agent (checkout, dev server). "Interrupt-chained resumes silently drop directives."
- Code-coupled work -> single owner that fans out after the blocking phase; parent-level fan-out only for independent artifacts (feature.md tail).
- `swarm`: spawn all N in one message, `PASS|ISSUES|BLOCKED` reports with named SHAs and method; drop results missing SHAs, respawn once, then record a gap (gap != pass). `arena`: same brief to N, base+graft. `interrogate`: same prompt to model families (Opus/GPT/Grok defaults), diversity not personas.
- Roles at scale (orchestrate.md "Roles"): Coordinator (never edits code; completions are queue events, drained at 4 points via `orch inbox drain`), optional Sub-coordinator per track (depth <=3, ~10 in-flight rolling window, not blocking batches), Worker/Verifier on cloud, verifier on different model family from worker. Hard-coded swarm trees "tried and parked as too rigid".
- Less micromanagement: the brief is the product (template GOAL/SCOPE/CONTEXT/ACCEPTANCE/VERIFY/TIMEBOX/FORBIDDEN/REPORT/STANDING; orchestrate.md "The brief"); standing-orders register `preferences.md` pasted verbatim into every spawn/resume because "directives decay across resumes"; refuse-to-spawn if fields missing; sampled brief audit alongside each wave. Probe liveness read-only by side effects (commits, pushes, PR/check deltas), never by resuming ("Transcript mtime is not liveness"); stuck lane gets replaced without waiting; retries by failure mode (cap/oom -> smaller scope; network -> as-is; tool-error -> different model; unknown once; two retries then abandon and replan). Hourly `/loop 1h` audit tick re-reads the playbook from trunk (`git show origin/main:...`) and posts a status only if a tracked change is unreported.
- Conflict avoidance: single writer on topology (root rebases chain bottom-up; owners push only own branches); workers never rebase; babysitters report conflicts upward; PR close/retarget only by stacker; self-contained PRs branch off main, "merge-then-branch" for sequenced work (autopilot-full step 3). Scope leaks parked in follow-ups.

## 5. PR slicing

- "Prefer five narrow PRs to one large PR" (opening-a-pr.md "Size and stacks"). Each commit is a future PR: landable, ordered to tell the story. `principle-sequence-verifiable-units`: canonical shape = failing test first, fix on top; other orders: subtract before reshape, baseline capture before treatment, scaffold before feature.
- Stack = base-branch chain: root PR targets trunk, child branch rebased on parent's exact tip, child PR targets parent branch (`gh pr create --base <parent>` / `gh pr edit <pr> --base <parent>`). Forge: `gh` default; `origin pr ...` (Origin CLI) if `command -v origin` works; "Do not require Graphite (`gt`)", "Never submit or register the chain through gt". No gh-stack, git-town, spr usage found (grep). Only Origin and gh.
- Unit of work in plans: one PR = one change with its own evidence; plan file sections per PR with `Depends on`, `Files`, `Build`, `You see` (observable result with exact log line/screen state), `Verify unit/live/perf`, `Review gate`, `Merge` (multi-phase-plan.md skeleton). Dependency graph states which PRs are independent (branch from main) and which wait for parent merge.
- Landing: bottom-up, only contiguous verified run; re-check each verdict against recorded (head SHA, base SHA, `git patch-id` of base-to-head diff); patch-id-equal rebase keeps the code verdict but re-runs mergeability+CI; patch changed -> fresh swarm (shipping.md step 3). Don't arm descendants; recompute after each merge. A babysit does not start when PR opens; finish the stack first (stalls build, spends CI on commits later waves restart).
- Fixes land in the lowest owning PR; if that PR already merged, new PR on top (babysit.md steps 4, 8).

## 6. Continuity, autonomy, durability

- Autonomy grants via phrases: "going to bed / don't stop / run until done" keep going (SKILL.md Autonomy); always-pause list: force-push to shared branches, deploys, data deletion, customer messages. "No is an acceptable answer": candor over sycophancy. Overnight contract (guide 07): goal + checkable finish condition + permissions + escape hatch; "a duration is not a finish condition".
- `autonomous-run.md`: predicate first, `/loop` wake (event watcher subagent + long heartbeat, else fixed heartbeat), smallest change, keep/discard, checkpoint row each iteration, plateau = pivot not stop, never relax predicate.
- Durability (what hits disk, when): `decisions.tsv` (show-me-your-work; local/gitignored by default, commit when auditable record needed; append-only, supersede wrong rows; `start` row for each new run/pickup; end-of-run audit of log vs transcript; cross-model reviewer + "Attention" section in reply). Owners start the trail within ~15 min, push first branch snapshot, open PR ready before self-proof "so URL, decisions, checks form a durable trail", push after every verifiable unit (WIP commit fine); `children.tsv` records subagent id/expected runtime/state. orchestrate store is the postmortem and "a unit is not done until its output is externalized the moment it lands... Work that exists only on one VM when that VM dies was never done."
- `pause-safely.md`: finish/back out atomic step, cancel nested agents, no irreversible action, one `wip:` commit, resume note (intent, doing, progress/verified, state, next steps, key files, gotchas) at `/tmp/<slug>-resume.md` or point at the trail.
- `session-pickup.md`: find prior trail (transcript in the active workspace only, cloud-agent URL, pushed branch), reconstruct state (branch, `git log`, open todos), diff done vs pending, "Resist the bias to re-derive it... 'let me verify from scratch' means you're treating the trail as untrustworthy", route remaining work, but verify inherited claims against the goal on the real artifact.
- Cursor restart recovery (orchestrate): local agents dead, cloud not; re-read standing orders + `units.tsv`, recompute frontier, reattach cloud work by PR/branch not agent id, respawn per-track sub-coordinator from stored brief.
- `recall`: fan out cheap subagents over transcripts (`ls -t` mtime order, topic grep first) + sweep shared record via `why`; returns state capsule. `reflect`: 3 reviewers over transcript -> concrete edits to skills. `automate-me`: mine history for your conventions -> `<handle>-mode` skill. Lessons loop: one-off -> note, recurring -> skill/lint, systemic -> principle.
- Model/budget config: `/setup-pstack` writes `~/.cursor/rules/pstack-models.mdc` (mirror: `~/.agents/pstack-models.md`); roles incl. code delegates, hardest tasks, judgment and prose, swarm workers, panel lists for arena/architect/interrogate; budget unlimited/large/medium/small remaps effort tokens.

## 7. Testing philosophy and gates

- Gate wording used verbatim everywhere (and linted by `check-plan.mjs`): "Tests alone are not sufficient verification. A PR is verified only when its unit, live, and perf boxes are all checked." Live = ten swarm lanes on the real surface at PR head, each with scenario, saved screenshot path (`/tmp/swarm-<pr>/worker-<n>/<slug>.png`) and pass predicate; lane 1 is a regression lane run on trunk and head (if trunk lacks the feature: gate the added behavior + the end state the user waits for). Perf = dual-sided, trunk baseline measured first, interleaved probe, rule with the failing number; no ratio between unlike scenarios.
- Per round: one gates lane (re-run gates at SHA), ten live lanes, perf lane, >=2 audit lanes that "distrust the PR body" with distinct focus (parity with trunk, lifetimes/races, data/config safety). Clean only if every lane PASS; "a defect that a lane filed as a note is a finding"; each behavior finding requires a red test covering every site with the same defect, or a repro receipt when no test can show it.
- `principle-test-behavior-not-implementation`: "would the test still pass if every imported function returned `undefined`?" — five shapes to reject (weak assertion, mock-only, self-referential, constant pin, fixture-asserts-fixture); assert literal expected output. `tdd`: failing test first only if cheap; "Prefer no new test over a bad test"; closest executable check otherwise. `principle-prove-it-works`: suspect the observation method when something passes too easily. `explain-the-number` + `benchmark-checklist`: vet limiter/repeatability/whether work happened before reporting a metric. Hillclimb: harness must print error count + count of work done, prove sensitivity on contrasting workloads, freeze, median of N, accept only past noise with regression gate green.
- Fixes: "Every shipped line traces to runtime evidence. Belt-and-suspenders that 'might help' is a hypothesis... does not ship" (bug-fix.md). Unit tests "show branch behavior, not bug absence."
- Ledger verdict quality ladder (`orch`): behavioral work needs better than `type-check-only`; `verifier-blocked` is not a pass; `verifier-failed` -> fix unit, not re-verify.
- `blast-radius`: pick the one fact the change is safe because of, prove by running real code.

## 8. Ideas worth stealing for workit

1. **Verification keyed to (PR, head SHA) + patch-id carry-over.** Ledger TSV with fixed verdict enum; a rebase voids verdicts unless `git patch-id` of base..head is unchanged (then re-run CI/mergeability only). Cheap, deterministic, kills "verified at an old SHA" (shipping.md step 3; store.ts `LEDGER_HEADER`).
2. **Author != verifier, enforced structurally;** CI-green and bot-approval explicitly not verdicts. Verdict recorded by an agent on a different model family.
3. **Contiguous verified run from the stack root** as the landing rule; report the "ceiling" PR and what breaks the chain.
4. **Project-local verification skill generated from the repo** (Launch / Doctor / Drive / Evidence / Cleanup + feature map, proven once end-to-end before use; periodic `maintain` pass limited to that skill's directory, outcomes clean/changed/blocked). Directly addresses "human is meat proxy".
5. **Question classifier:** ask the human only for preference/product calls; anything observable becomes a Prototype run. Under autonomy grant: decide, act, report default and what operator could say instead (no shorthand tokens to type back).
6. **Playbook = checklist copied verbatim into the todo list**, with `skip: <reason>` for omitted steps; plan files validated by a linter (`check-plan.mjs`) so structure is machine-enforced, not hoped for.
7. **`orch`-style plain-file store:** one writer per file, TSV/JSON, status derived not hand-edited, dead-pid lock stealing, `inbox` pointers drained in batches, `gates.md` with default-on-no-answer, `preferences.md` standing orders re-pasted every spawn. Re-read playbook from `origin/main` each tick to avoid drifting from the contract.
8. **Brief template with refuse-to-spawn on missing fields** and per-wave sampled brief audit; fresh agent with consolidated scope instead of resume-chains.
9. **Side-effect liveness:** judge agents by commits/pushes/PR/check deltas; stuck -> replace immediately; retry policy by failure mode, max two.
10. **Decision-trail TSV** (`ts phase decision why evidence result`, append-only, supersede-not-edit, `start` row per run for pickups, end audit against transcript, cross-model "Attention" section). `log.sh` sanitization is a nice touch.
11. **`watch-pr` as the only wake source** (JSON verdicts, typed blocker classes, order conflicts > threads > CI, one retry for flake only after classifying; stale-base check via `merge-base --is-ancestor`). No second sleep loop.
12. **PR body as briefing:** fixed `##` sections, <~40 line squash body, perf number as `before -> after`, evidence in linked artifacts not the body.
13. **Pause/pickup pair:** `wip:` commit + resume note; pickup trusts the prior trail and only verifies claims against the goal.
14. **`principle-encode-lessons-in-structure` as meta-rule:** second time you write an instruction, make it a script/lint. Plus `reflect`/`automate-me` to feed corrections back into skills.
15. **Single writer on stack topology, many writers on builds;** babysitter never rebases; fixes land in the lowest owning PR; don't start babysit until whole stack exists.
16. **Hillclimb discipline** (frozen harness, one change/one measurement/keep-or-revert, decision.tsv) for metric work.

## 8b. Anti-patterns and costs (observed in the source)

- **Ceremony cost is enormous.** Verification of one PR = 1 gates + 10 live lanes + perf + >=2 audit lanes, each cloud agent, re-run on every patch-changing push; hourly audit ticks; sub-coordinators; cross-model trail review. The source itself warns: ceremony must scale with the program; "a verifier agent whose entire product would be rerunning one command is ceremony"; "a 4KB scaffold around a two-line edit costs more to write and obey than the edit"; babysit-per-PR "stalls the build". Orchestrate routes small work back out. Workit should copy the scaling rule, not the ten-lane default.
- **Cursor lock-in:** relies on `/loop`, cloud-agent `environment`, `control-ui/cli`, `deslop`, Bugbot, Cursor transcripts path, per-role model slugs (grok-4.7, claude-opus-5-5, gpt-5.6-sol — fast-aging config). Mirror needed a Harness shim; it has no cloud agents, so "each live lane on its own cloud VM" degrades to local worktrees.
- **Hidden Graphite coupling:** prose forbids `gt`, but `orch frontier set`/orchestrate "Stack safety" compute the frontier "from gt" and give one stacker the `gt` role. Internal inconsistency; avoid.
- **Prompt-only enforcement of most rules;** only `orch`, `watch-pr`, `check-plan.mjs`, `worktree-audit.sh`, `log.sh` are code. Rules like "never babysit on PR open", "delegate is mandatory", "read the leaf principle before citing" depend on model compliance; the principle `encode-lessons-in-structure` is aspirational for most of the plugin. Huge prose surface (~98 KB of playbooks, skills with long run-on rule paragraphs) = context cost and drift risk; `poteto-agent` must reread all of SKILL.md every spawn.
- **Style policing as workflow:** unslop/no-long-dash/no-colon rules, Comment Sicko deleting comments, mandatory `no-comments` and `deslop` per PR — opinionated, personal taste baked into gates.
- **Mandatory delegation** ("no skip-with-reason escape, Laziness Protocol does not override") adds a model hop even for trivial diffs; justified as review separation but costs tokens/latency.
- **Autonomy surface:** "Just do it. Use any MCP tool" with team-chat/ticket writes proceeding unasked; irreversible list is short. Merge authority granted by phrase plus an LLM swarm verdict (autopilot-full) — high trust in LLM verifiers.
- **Operational fragility acknowledged by the authors:** zombie agents returning late, directive decay across resumes, store lock after crash, GitHub base-ref drift mid-restack, `autoMergeRequest` not meaning stack readiness, auto-merge into a parent PR collapsing review granularity (babysit.md step 6). These explain the machinery but also show how much state a multi-PR stack run must police.
- Third-party view (kayvane): "fifteen predefined playbooks", manual maintenance when adding principles to playbook steps.
