# Challenge open choices with evidence

Skip this method for a precise, settled request.

## Method

1. Ground the outcome, constraints, evidence, and important unknowns. Inspect
   code and project docs before asking about facts they can answer.
2. Separate observations, inferences, and proposals. Test assumptions that
   could change the recommendation.
3. When viable alternatives exist, present two or three genuinely different
   approaches. Recommend one; for each, give its benefit, cost or risk, when it
   fits, and the smallest useful validation. Do not invent a weak alternative.
4. Ask only consequential questions, in dependency order. Group independent
   choices into one small round. If an authorized reversible default works,
   state it and proceed.
5. Record a settled choice once in the existing conversation or task context.
   A discussion decision is knowledge, never a permission; do not reopen it
   without new evidence.
6. Create durable documentation only when requested or when the decision needs
   a future reader. Brainstorming alone does not require a spec.

Say directly when evidence shows a proposal is weak, overcomplicated, or solves
the wrong problem. Raise a counter-case only when it adds a real constraint.

## Guardrails

- Do not create a universal spec, plan, approval chain, or second lifecycle.
- Unknowns that affect an action remain unresolved until evidence or a user
  decision closes them.
- Use shared operations for tracked state and provenance; never write task
  metadata directly.
- An in-session counter-case is not fresh-context review.

## Common mistakes

| Mistake | Correction |
| --- | --- |
| Asking what code or docs already answer | Ground first; the user owns choices, not lookups. |
| Listing every hypothetical objection | Raise only objections that can change the decision. |
| Asking for agreement without a recommendation | Recommend an option and explain the tradeoff. |
| Treating a discussion decision as permission | Record it as knowledge; preserve native host authority. |
